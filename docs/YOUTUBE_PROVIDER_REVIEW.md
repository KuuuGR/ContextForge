# YouTube Provider Technology Review

## Executive Summary

The application reproduces a real user failure: both Debug and Release builds fail to retrieve metadata from valid YouTube URLs.

The failure was traced in Phase 020 (`ROOT_CAUSE.md`) to a **missing macOS App Sandbox network-client entitlement**, not to the YouTube provider library. The runtime trace captured `SocketException: Connection failed (OS Error: Operation not permitted, errno = 1), address = www.youtube.com, port = 443` — the classic sandbox `EPERM` denial.

This review verifies whether `youtube_explode_dart` remains the correct technical choice given that the failure exists in both builds.

## Known Issues

The GitHub repository has 62 open issues. The library is a scraping-based client (no official YouTube API key), which inherently carries risk when YouTube changes its HTML/player structure. However:

- **No recent regression found** affecting metadata retrieval at the library level.
- The library's `videos.get()` (which the project calls for metadata) is the core, long-stable path.
- Transcript/caption support (via `closedCaptions.getManifest` / `closedCaptions.get`) is present and was exercised in Phase 018 diagnostics before the sandbox issue was identified.

## Compatibility With Modern YouTube

The library is a scraping client that reads metadata and transcripts from YouTube pages. Key capability check:

| Capability | Supported | Notes |
|------------|-----------|-------|
| Video metadata | ✅ | title, channel, publish date, duration, URL, description |
| Transcript track discovery | ✅ | `closedCaptions.getManifest` |
| Transcript download | ✅ | `closedCaptions.get` |
| Auto-generated captions | ✅ | `isAutoGenerated` flag on track info |

The **verified provider level** pipeline (outside the sandbox, via `flutter test` in Phase 018) completed the full flow against a real video (`OPZczs-Kttg`): metadata → 5 transcript tracks discovered → selection → 420 segments downloaded. This demonstrates the **library is functionally compatible** with YouTube's current transcript system.

The runtime failure (`errno = 1`, Operation not permitted) originates **before any YouTube response is parsed** — it is a sandbox socket denial at the OS level, which occurs whether the provider is `youtube_explode_dart` or any other network-based provider.

---

## Is the Issue Application Code, Provider Usage, Provider Limitation, Provider Regression, or YouTube Changes?

| Category | Verdict | Evidence |
|----------|---------|----------|
| Application code | ❌ | Runtime trace shows the failure occurs at the socket connect boundary, inside the OS sandbox, before any application logic is reached |
| Provider usage | ❌ | The project calls `yt.videos.get(videoId)` correctly; same call succeeds outside the sandbox |
| Provider limitation | ❌ | Provider supports metadata, transcripts, captions; full pipeline verified outside sandbox |
| Provider regression | ❌ | No recent regression found; latest version 3.1.0 is actively maintained |
| Recent YouTube changes | ❌ | No evidence; the same pipeline succeeded against YouTube in Phase 018 diagnostics (outside sandbox) |
| **Missing sandbox entitlement** | **✅** | `com.apple.security.network.client` absent from both `DebugProfile.entitlements` and `Release.entitlements`; runtime trace proves `EPERM` at socket layer |

The failure is **not** caused by the provider. It is caused by the application's macOS App Sandbox configuration.

## Alternatives

| Alternative | Type | Assessment |
|-------------|------|------------|
| `youtube_explode_dart` (current) | Scraping (no API key) | Actively maintained, latest version in use, supports all required features |
| Official YouTube Data API v3 | Official REST API | Requires API key + quota management; network stack still blocked by the same missing entitlement |
| `youtube_transcript_api` (Python/C# ecosystem) | Transcript-focused | Not a Dart package; would require platform channel or service — larger architectural change |
| Custom scraper | In-house | Would re-implement what `youtube_explode_dart` already provides; higher maintenance cost |

No alternative provider solves the observed failure, because the failure is a sandbox entitlement issue that affects **any** outbound network connection.

---

## Recommendation

**KEEP**

- The project already uses the latest version (`3.1.0`) of an actively maintained library.
- The library is functionally compatible with YouTube's metadata and transcript systems (verified end-to-end outside the sandbox in Phase 018).
- The observed failure is a macOS App Sandbox entitlement issue (`com.apple.security.network.client` missing), not a provider issue — replacing the provider would not fix it.
- The correct architectural action is to add the missing network-client entitlement (proposed in `ROOT_CAUSE.md`), not to change providers.
